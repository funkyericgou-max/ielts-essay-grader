# 已知局限与风险

## 写作评分风险（现有）

| 风险 | 程度 | 应对 |
|------|------|------|
| AI 评分与官方结果可能存在偏差 | **高** | 明确标注「AI 辅助评分」；通过 Band Descriptors 量表 + 三步法 + 量化对齐规则尽量校准 |
| 同一篇作文多次评分结果不一致 | 中 | 设置 temperature=0.3 降低随机性 |
| API 调用有延迟 | 中 | 添加加载动画 + 轮播提示文案 |
| 输出 JSON 格式异常（含 Markdown 包裹或截断） | 中 | 前端做健壮的解析和容错：正则去噪 + Try-Catch + Fallback textarea |
| 长作文 + 长 Prompt 可能超过 Token 限制 | 低 | 控制 Prompt 长度，必要时截断 |
| API Key 暴露风险 | 低 | 仅存在 localStorage，不上传 GitHub；Key 有使用量限制即可控 |

## 口语评分风险（新增）

| 风险 | 程度 | 应对 |
|------|------|------|
| **STT 转写错误导致评分偏差** | **中** | Whisper large-v3 准确度高；转写文本与原始音频均可回听供人工核对；User Prompt 告知 AI 容错转写误差 |
| **发音评分依赖间接推断，准确度有限** | **高** | P 维度 analysis 中强制标注"AI 推断，仅供参考"；前端提取音量变化等元数据增加推断依据；未来若接入多模态模型可直接分析音频 |
| **填充词检测可能漏检或误检** | 中 | 中英文混合语境下填充词模式复杂；正则匹配覆盖常见填充词；AI 可在评分中二次校验 |
| **停顿检测受环境噪音影响** | 中 | 使用自适应阈值（相对于平均 RMS）；建议用户在安静环境录音；前端提示"请在安静环境中录音" |
| **Groq Whisper 未来可能收费或限制** | 低 | 目前无限免费；架构预留切换 STT 提供商的能力（接口与 OpenAI Whisper 兼容，可无缝切换） |
| **浏览器兼容性（录音功能）** | 中 | MediaRecorder 在 Chrome/Firefox/Edge 中普遍支持；Safari 需注意 MIME 类型兼容（降级为 audio/mp3）；iOS Safari 需 HTTPS（GitHub Pages 天然满足）；IE 不支持 |
| **麦克风权限被拒** | 中 | 捕获 `NotAllowedError`，引导用户在浏览器设置中开启麦克风权限；提供「手动输入转写文本」降级方案 |
| **录音文件过大** | 低 | 2 分钟口语约 1-2MB WebM，远低于 Groq 25MB 限制；前端可设置最长录音 5 分钟 |
| **用户网络环境差 → STT + 评分双重延迟** | 中 | STT 和评分为串行调用（先转写再评分），总耗时可能 10-30 秒；Loading 阶段展示分步进度："正在转写..." → "正在评分..." |
| **Groq API Key 安全** | 低 | 与 DeepSeek Key 同策略：localStorage 存储，不上传 GitHub |

## 通用风险

| 风险 | 程度 | 应对 |
|------|------|------|
| **代码量膨胀**（~2900 行 → ~4300 行） | 中 | 保持单文件按模块注释分隔；关键函数命名清晰；复杂逻辑封装为独立函数 |
| **三套交互逻辑维护成本** | 中 | 写作和口语共用 Prompt 框架 + JSON 结构范式；听力完全独立，无 API 依赖 |
| **移动端体验** | 中 | 首页三卡片在小屏纵向堆叠；口语录音按钮增大；听力 tile 自动换行 |

## 听力同义替换风险

| 风险 | 程度 | 应对 |
|------|------|------|
| **同义词数据有误差** | 低 | 数据来自专业雅思备考整理，经人工核对；用户可在游戏结果中看到漏选/误选详情，自行判断 |
| **游戏随机性导致体验不均** | 低 | 随机抽取 10 组确保每次开局不同；误选/漏选对应项已标出 |
| **陷阱词不参与游戏** | — | 陷阱词（数字、连读、拼写）形态不统一，v3 仅作 glossary 参考；未来可增加独立 quiz
