# 评分体系与量化对齐设计

## 一、写作评分（Writing）

### 官方 4 维度与任务差异

系统根据用户在前端选择的 Task Type，动态启用对应的官方量表和字数惩罚规则：

| 维度 | Task 1 (小作文) 考查重点 | Task 2 (大作文) 考查重点 |
|------|-------------------------|-------------------------|
| **TA** | **Task Achievement**：是否准确描述图表核心趋势、有无遗漏关键数据、有无主观臆断 | **Task Response**：是否回应题目所有部分、立场是否明确、论证是否充分有深度 |
| **CC** | **Coherence & Cohesion**：信息和数据排列是否逻辑清晰、连接词与指代是否自然 | **Coherence & Cohesion**：段落结构是否合理、逻辑推进是否清晰、衔接手段是否多样 |
| **LR** | **Lexical Resource**：数据与趋势描述词汇是否多样、学术词汇搭配是否准确 | **Lexical Resource**：词汇量是否充足、是否使用不常见词汇和地道搭配、有无重复 |
| **GRA** | **Grammatical Range & Accuracy**：时态是否准确（如历史数据用过去时）、复杂句比例 | **Grammatical Range & Accuracy**：句型是否多样、复杂句使用情况、语法错误频率 |

**Overall = (TA + CC + LR + GRA) ÷ 4**，四舍五入到最接近的 0.5 分（如 26 ÷ 4 = 6.5）。

### 前端本地量化约束条件

在请求前，前端在本地计算基础统计指标，并作为硬性约束条件传入 User Prompt：

| 指标 | 计算方式 | 意义 | 量表映射规则 |
|------|---------|------|------------|
| 总词数 | 按空格和标点分割，过滤空字符串 | 判断是否达到最低词数要求 | Task 1 < 150 \| Task 2 < 250 → TA ≤ 5.0 |
| 句子数 | 按句号/问号/感叹号分割 | 评估句长多样性 | — |
| 平均句长 | 总词数 ÷ 句子数 | 衡量句式复杂度 | < 12 → GRA ≤ 6.0 |
| 词汇类型比 TTR | 不同词数 ÷ 总词数 | 衡量词汇多样性 | < 0.45 → LR < 7.0 |
| 词形数 | 去重后的词汇数量 | 辅助判断词汇范围 | — |

## 二、口语评分（Speaking）

### 官方 4 维度

口语评分同样使用 4 个维度，但与写作有本质区别——**Fluency & Coherence 替代了 Task Achievement，Pronunciation 替代了 Coherence & Cohesion**：

| 维度 | 缩写 | 考查重点 | 与写作的对应关系 |
|------|------|---------|---------------|
| **Fluency & Coherence** | **FC** | 流利度：语速是否自然、停顿是否得当、自我纠正是否频繁；连贯性：逻辑推进是否清晰、衔接是否自然 | 🆕 口语独有，替代写作 TA |
| **Lexical Resource** | **LR** | 词汇灵活度：是否能灵活使用词汇表达观点；口语化搭配与习语：是否使用地道口语表达而非书面语；转述能力（paraphrase） | 与写作 LR 同维度，但侧重口语化 |
| **Grammatical Range & Accuracy** | **GRA** | 句型多样性：是否能灵活使用简单句和复杂句；语法错误频率：区分"系统性错误"与口语中的自然口误（slips） | 与写作 GRA 同维度，但对口误更宽容 |
| **Pronunciation** | **P** | 发音准确度：元音/辅音是否清晰准确；重音与节奏：单词重音和句子节奏是否自然；语调：是否能通过语调表达不同语义 | 🆕 口语独有，替代写作 CC |

**Overall = (FC + LR + GRA + P) ÷ 4**，四舍五入到最接近的 0.5 分。

### 口语独有的评分挑战

| 挑战 | 说明 | 缓解策略 |
|------|------|---------|
| **发音评分是间接的** | 纯文本 LLM 无法直接"听"音频 | 前端提取音频元数据（语速、停顿、音量变化等），AI 综合推断 |
| **流利度需要音频证据** | 停顿频率、语速、自我纠正无法从纯文本完全判断 | 前端分析 Web Audio API 数据 + 转写文本中的填充词 |
| **STT 转写误差** | 语音识别可能误转，导致评分基准偏差 | 选择高准确度 STT（Groq Whisper），必要时展示原始音频供人工对照 |

### 前端本地量化约束条件（口语）

在发送评分请求前，前端通过 Web Audio API + 文本分析计算以下指标：

| 指标 | 计算方式 | 意义 | 量表映射规则 |
|------|---------|------|------------|
| **语速 (WPM)** | 总词数 ÷ 录音时长(分钟) | 流利度核心指标 | < 100 wpm → FC ≤ 6.0（过慢）；> 180 wpm → 可能背诵，需关注自然度 |
| **停顿次数** | Web Audio API 检测 >0.5s 静音段 | 流利度 | 停顿 > 每 30 秒 5 次 → FC ≤ 5.5 |
| **填充词统计** | 正则匹配 um/uh/er/you know/like/well/I mean… | 流利度 | 填充词占比 > 5% → FC 上限 -0.5 |
| **自我纠正次数** | 检测重复词组/中途改口模式 | 流利度 | 频繁自我纠正 → FC 上限 -0.5 |
| **录音时长** | 秒 | Part 2 基准 | < 60 秒（Part 2）→ FC ≤ 5.0（内容不足） |
| **总词数** | 转写文本词数 | 基础指标 | < 100 词（Part 2）→ FC ≤ 5.0 |
| **TTR** | 去重词数 ÷ 总词数 | 词汇多样性 | < 0.45 → LR < 7.0 |
| **平均句长** | 总词数 ÷ 句子数 | 语法复杂度 | —（口语中短句未必是问题） |
| **音量变化 (Volume Variance)** | Web Audio API 分析 | 发音辅助 | 过于平淡的音量 → 可能缺乏语调变化，P 维度参考 |

### 口语评分算法（CoT 三步推理法）

与写作相同，但微调逻辑适配口语特点：

1. **【定档】**：从 Band 9 向下筛选，找到回答完全满足的最高整分档位
2. **【微调】**：结合量化指标（WPM、停顿、填充词等）决定是否 ±0.5
3. **【举证】**：从转写文本中摘录至少 2 处具体表达作为证据

### 口语强制量化清单

AI 评分时必须回答以下问题（写入 System Prompt）：

- **FC 清单**：语速是否在 120-150 wpm 正常范围内？停顿是否频繁（>5次/30秒）？填充词占比是否 > 5%？是否存在大面积背诵痕迹？
- **LR 清单**：TTR 是否 ≥ 0.45？是否使用了口语化搭配（phrasal verbs, idioms）？是否存在大量重复用词（≥3次）？
- **GRA 清单**：无错误句子占比？是否使用了复合句？错误是"系统性"还是"口误级"？
- **P 清单**：音量变化是否自然（反映语调）？语速变化是否有节奏感？是否有明显的单词重音问题（基于元数据推断）？
