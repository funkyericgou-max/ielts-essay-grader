# 详细开发与构建步骤

---

## 第一阶段：写作评分（已完成）

### 步骤 1: 升级输入面板与基础统计

- 在原 HTML 页面输入区上方，添加 Task 1 / Task 2 的 Toggle 切换组件
- 编写 JS 统计模块，提交时计算：总词数、句子数、平均句长、TTR
- 增加 API Key 配置浮层，输入后通过 `localStorage.setItem('deepseek_api_key', value)` 持久化

### 步骤 2: 动态 Prompt 组装与发送

- 绑定「开始批改」按钮事件：
  1. 读取 `localStorage` 中的 Key，若无则弹窗拦截引导输入
  2. 根据 Toggle 状态，将 Task 1 或 Task 2 的英文量表注入 System Prompt
  3. 将本地统计数据、题目、文章注入 User Prompt
  4. 切换 UI 为 Loading 状态，启动轮播提示文案

### 步骤 3: 打造健壮的响应解析模块（防御性编程）

- 接收到 DeepSeek 返回的 string 后：
  - **正则去噪**：`res.replace(/^```json\s*/i, '').replace(/```$/, '').trim()`
  - **Try-Catch 捕获**：`try { JSON.parse() } catch (e)`
  - **Fallback 兜底**：若解析失败，将原始文本放入滚动条 textarea 呈现给用户，绝不白屏

### 步骤 4: 动态数据渲染与 Tab 填充

- **评分总览 Tab**：填充 `prompt_analysis` 和 `evaluation_justification` 中的 4 维度卡片
- **作文批注 Tab**：`container.innerHTML = json.annotated_essay`，利用 CSS 对 `.ielts-grammar`、`.ielts-vocab` 等类名赋予不同高亮色
- **语法分析 Tab**：遍历 `grammar_issues_list` 渲染为可折叠手风琴组件
- **详细反馈 Tab**：填充优缺点卡片及 `coherence_flow` 宏观诊断文本
- **行动建议 Tab**：渲染 `next_steps` 中的 3 条精准行动点
- **侧边栏**：渲染 4 维度分数及 Overall 总分

### 步骤 5: 交互完善

- 按钮 loading 状态（禁用 + 加载动画 + 轮播提示文案）
- 错误提示 UI（网络错误/API 返回异常/超时）
- 重新批改功能（返回输入面板 + 保留原输入内容）
- API Key 配置界面（input + localStorage 持久化）

## 第二阶段：口语评分（新增）

### 步骤 6: 首页重构 — 模块选择入口

- 新建首页视图（`#homePage`），展示 Writing / Speaking 两张入口卡片
- 顶栏新增「← 返回首页」按钮
- `AppState.mode` 状态管理：`'home'` | `'writing'` | `'speaking'`
- 点击卡片后切换到对应工作区，隐藏首页
- 原有写作面板整体包进 `#writingWorkspace`

### 步骤 7: 口语输入面板 — Cue Card + 录音区

- 新建 `#speakingInputPanel`：
  - Cue Card 题目 textarea（可折叠）
  - 预设示例题目下拉选择
  - 「加载示例」按钮（加载示例 cue card + 模拟转写文本，供无麦克风环境测试）
- 录音操控按钮组：
  - `[🔴 开始录音]` — 请求麦克风权限，启动 MediaRecorder
  - `[⏸️ 暂停]` — 暂停录音（保留已录音频）
  - `[⏹️ 停止并保存]` — 停止录音，产出 audioBlob
  - `[▶️ 播放回听]` — 播放已录音频
  - `[🔄 重新录制]` — 清除当前录音
  - `[📤 提交评分]` — 触发评分流程
- 录音时长计时器（`⏱ 00:00` 格式）
- Canvas 实时波形可视化

### 步骤 8: 音频录制模块 (AudioRecorder 类)

- 封装 `navigator.mediaDevices.getUserMedia({ audio: true })`
- MediaRecorder API，优先 `audio/webm;codecs=opus`，Safari 降级 `audio/mp3`
- 权限被拒时提示并引导用户开启，「手动输入转写文本」降级方案
- 录音超过最长时长（5分钟）自动停止
- 最短时长校验（30 秒）— 过短拦截提示

### 步骤 9: 音频分析模块 (AudioAnalyzer 类)

- 使用 `AudioContext.decodeAudioData()` 解码 audioBlob 为 AudioBuffer
- 计算指标：
  - **录音总时长**：`audioBuffer.duration`
  - **语速 (WPM)**：需等 STT 转写完成后计算（词数 ÷ 时长分钟）
  - **停顿检测**：按 100ms 帧分析 RMS（均方根振幅），连续 5 帧低于阈值 → 标记停顿
  - **停顿统计**：总次数、总时长、停顿占比（`pause_ratio`）
  - **音量变化**：各帧 RMS 的方差（反映语调起伏）
  - **有效语音段占比**：去除首尾静音后的有效语音比例
- 分析结果打包为元数据 JSON 对象

### 步骤 10: STT 转写模块 (Groq Whisper)

- 封装 `callGroqWhisper(audioBlob)`：
  - 构建 FormData，append audioBlob + model + language + response_format
  - `fetch()` → `https://api.groq.com/openai/v1/audio/transcriptions`
  - 解析 `verbose_json` 返回值：`{ text, segments[{start, end, text}], language }`
  - 错误处理：网络错误/超时 → 重试 1 次 → 仍失败则提示「转写失败，请重试或手动输入回答文本」
- Groq API Key 管理：
  - 无 Key 时弹窗引导设置
  - 设置弹窗新增 Groq Key 输入框
  - Key 存储在 `localStorage.getItem('groq_api_key')`

### 步骤 11: 转写文本分析

- 对转写文本计算：
  - 总词数、句子数、TTR、平均句长
  - 填充词正则匹配：`/\b(um|uh|er|ah|hmm|like|you\s*know|i\s*mean|well|sort\s*of|kind\s*of)\b/gi`
  - 填充词占比：填充词数 ÷ 总词数
  - 自我纠正检测：重复词组模式（如 "I went to... I went to..."）

### 步骤 12: 口语 Prompt 组装

- `buildSpeakingSystemPrompt()`：注入口语 Band Descriptors + CoT 三步法 + 音频元数据使用指南
- `buildSpeakingUserPrompt()`：打包 cue_card_text + transcript_text + 所有音频元数据
- 复用现有 `callDeepSeekAPI()` 函数，仅 Prompt 不同

### 步骤 13: 口语结果渲染

- **侧边栏**：渲染 FC/LR/GRA/P 分数条 + 口语统计卡片（WPM / 停顿 / 填充词 / TTR）
- **Tab 1 - 评分总览**：题目分析卡片 + 4 维度评分卡片
- **Tab 2 - 转写批注**：`innerHTML` 渲染 `transcript_annotated`
- **Tab 3 - 语法分析**：可折叠手风琴（复用写作组件）
- **Tab 4 - 流利度分析**：Canvas/SVG 绘制语速仪表盘 + 停顿分布图 + 填充词统计图
- **Tab 5 - 详细反馈**：优缺点 + `fluency_analysis` 文本
- **Tab 6 - 行动建议**：3 条改进建议
- CSS 新增口语标注类：`.ielts-fluency`（黄色）、`.ielts-pronounce`（粉色）

### 步骤 14: 口语交互完善

- 录音状态机管理（初始/录制中/暂停/已保存/评分中）
- 按钮禁用状态联动
- Loading 覆盖层 + 口语主题提示文案轮播（"正在转写录音..." / "正在分析流利度..." / "正在评估发音特征..."）
- 「重新录制」保留 cue card 题目
- 「返回首页」可随时切换模式
- 移动端适配：录音按钮增大、波形简化

### 步骤 15: 设置弹窗扩展

- 新增 Groq API Key 输入框
- 注册链接：`console.groq.com`（标注"免费注册，无需绑卡"）
- Groq Key 缺失时，仅在口语模式拦截；写作模式不受影响
- 两个 Key 的保存/加载逻辑独立
