# 技术架构

## 一、整体架构

### 写作评分链路

```
用户输入 (选择 Task 类型 + 题目 + 作文)
    │
    ▼
前端本地计算 ──────→ 基础统计（词数/句数/TTR/平均句长）
    │
    ▼
JS 动态组装 ──────→ 根据 Task 类型，抽取对应的官方 Band Descriptors 量表
    │
    ▼
构造 API 请求 ──────→ System Prompt（含 CoT 三步算法 + 量化对齐 + 全文标签规则 + JSON 顺序约束）
                      + User Prompt（含统计数据 + 文本）
    │
    ▼
DeepSeek Chat API（temperature=0.3，低随机性稳定输出）
    │
    ▼
前端健壮解析 ──────→ Try-Catch 捕获机制（预防 JSON 截断，提供源码级 Fallback 渲染）
    │
    ▼
动态渲染 UI ──────→ 使用 innerHTML 直接渲染带标签的全文批注，其余字段填充各 Tab
```

### 口语评分链路

```
用户录音 (MediaRecorder API, WebM Opus)
    │
    ├─→ 前端音频分析 (Web Audio API + AnalyserNode)
    │     ├─ 语速 WPM
    │     ├─ 停顿次数/时长/分布
    │     ├─ 音量变化 (反映语调)
    │     └─ 有效语音段占比
    │
    └─→ Groq Whisper API (STT 转写)
          │
          ▼
     转写文本
          │
          ├─→ 前端文本分析
          │     ├─ 总词数 / TTR / 平均句长
          │     ├─ 填充词统计 (um, uh, like...)
          │     └─ 自我纠正次数
          │
          ▼
     JS 动态组装 ──────→ 口语 System Prompt (含 Band Descriptors + CoT 三步 + 音频元数据约束)
                          + User Prompt (转写文本 + 所有量化指标)
          │
          ▼
     DeepSeek Chat API（temperature=0.3）
          │
          ▼
     前端健壮解析 ──────→ Try-Catch + 正则去噪 + Fallback
          │
          ▼
     动态渲染 UI ──────→ 6 个 Tab (含流利度可视化图表)
```

## 二、技术选型

| 层级 | 技术 | 原因 |
|------|------|------|
| 前端 | 纯 HTML + CSS + JavaScript | 单文件部署、无依赖、便携 |
| 写作评分 | DeepSeek Chat API | 高性能、性价比高、中文友好 |
| 口语评分 | DeepSeek Chat API | 同上，口语评分本质是文本+元数据推理 |
| 语音转文字 | **Groq Whisper API** (`whisper-large-v3`) | **无限免费**、50+语言、LPU 加速 |
| 音频录制 | MediaRecorder API (WebM Opus) | 浏览器原生、零依赖 |
| 音频分析 | Web Audio API (AudioContext + AnalyserNode) | 浏览器原生、实时分析 |
| 前端可视化 | Canvas + SVG | 零依赖，绘制流利度图表 |
| API Key | 浏览器 localStorage | 用户自行填入，不上传 GitHub |
| 托管 | GitHub Pages | 纯静态，免费，小规模使用 |

## 三、API 配置

### DeepSeek（写作 + 口语评分）

```javascript
const DEEPSEEK_CONFIG = {
  endpoint: 'https://api.deepseek.com/v1/chat/completions',
  model: 'deepseek-chat',
  apiKey: localStorage.getItem('deepseek_api_key'),
  temperature: 0.3,
  maxTokens: 8192
};
```

### Groq Whisper（语音转文字）

```javascript
const GROQ_CONFIG = {
  endpoint: 'https://api.groq.com/openai/v1/audio/transcriptions',
  model: 'whisper-large-v3',
  apiKey: localStorage.getItem('groq_api_key'),
  language: 'auto',       // 自动检测，也可指定 'en' / 'zh'
  response_format: 'verbose_json'  // 返回分段结果（含时间戳）
};
```

### 音频录制配置

```javascript
const AUDIO_CONFIG = {
  mimeType: 'audio/webm;codecs=opus',  // 优先 WebM Opus
  fallbackMimeType: 'audio/mp3',       // Safari 降级
  sampleRate: 48000,
  channelCount: 1,        // 单声道
  maxDuration: 300,       // 最长录制 5 分钟
  minDuration: 30         // 最短 30 秒（Part 2 要求 1-2 分钟）
};
```

## 四、前端模块结构（`index.html` 内 JS 区域划分）

| 模块 | 大致区域 | 说明 |
|------|---------|------|
| 状态管理 | `appMode` 变量 | `'home' \| 'writing' \| 'speaking' \| 'listening'`，管理全局状态切换 |
| 首页渲染 | `#homePage` HTML | 渲染 Writing / Speaking / Listening 三张入口卡片 |
| 写作完整链路 | 现有代码 | 输入 → 统计 → API → 解析 → 渲染（保持不变） |
| 录音管理 | `AudioRecorder` 类 | `start()` / `pause()` / `resume()` / `stop()` / `playback()` |
| 音频分析 | `AudioAnalyzer` 类 | `getWPM()` / `getPauses()` / `getVolumeVariance()` / `getSpeechDuration()` |
| 波形绘制 | `WaveformRenderer` 类 | Canvas 实时波形，`requestAnimationFrame` 驱动 |
| STT 调用 | `callGroqWhisper()` | FormData 上传音频 → 返回转写文本 |
| 口语评分 Prompt | `buildSpeakingSystemPrompt()` / `buildSpeakingUserPrompt()` | 动态注入口语 Band Descriptors + 音频元数据 |
| 口语结果渲染 | `renderSpeakingResults()` | 填充侧边栏 + 6 个 Tab（含流利度可视化图表） |
| 听力同义词数据 | `LISTENING_CATEGORIES` / `LISTENING_ALL_PAIRS` / `LISTENING_TRAP_GROUPS` | 115 组同义词对 + 陷阱词，JS 常量嵌入，零请求 |
| 听力大纲展示 | `renderListeningGlossary()` + `filterListeningGlossary()` | 8 分类可折叠列表 + 搜索过滤 + 陷阱词卡片 |
| 听力游戏引擎 | `startListeningGame()` → `buildListeningRound()` → `submitListeningRound()` → `goNextListeningRound()` | 10 轮匹配，tile 点选判定，正确/误选/漏选着色 |
| 听力结果导出 | `exportListeningResult()` | Markdown 报告 Blob 下载 |

## 五、数据流关键点

### 音频 → STT → 评分 时序

```
1. 用户点击「开始录音」 → AudioRecorder.start()
2. 用户点击「停止并保存」 → AudioRecorder.stop() → 获得 audioBlob
3. 用户点击「提交评分」：
   a. AudioAnalyzer.analyze(audioBlob) → 元数据 JSON
   b. callGroqWhisper(audioBlob) → 转写文本
   c. 前端文本分析(转写文本) → 填充词/自我纠正/TTR
   d. buildSpeakingSystemPrompt() + buildSpeakingUserPrompt()
   e. callDeepSeekAPI() → 评分 JSON
   f. renderSpeakingResults()
```

### 听力游戏链路（纯客户端，零 API）

```
用户选择分类范围 → 随机抽取 10 组同义词对
  → buildListeningRound(): 随机选 target 词 + target 侧
  → 生成 tile grid（正确答案含中文释义 + 干扰项 → shuffle）
  → 用户点选 tile → 提交判定
  → submitListeningRound(): 逐 tile 判定正确/误选/漏选 → 着色
  → 侧边栏实时更新进度 / 正确率 / 连对 / 分类掌握度
  → 用户点击「下一题」→ goNextListeningRound() → 下一轮或 finishListeningGame()
  → 10 轮结束后展示完整结果 + 错误回顾 → 可选 Markdown 导出
```

### 错误处理

```
录音权限拒绝 → 提示用户允许麦克风权限，并提供「手动输入转写文本」的降级方案
STT 失败 → 重试 1 次，仍失败则提示用户手动输入回答文本
评分失败 → 现有防御解析链路 (正则去噪 → JSON.parse → Fallback textarea)
Key 缺失 → 仅在提交时按需提示；首次访问引导窗口可选择「暂不设置」跳过
听力 → 无服务端依赖，无法失败
```
