# 60 天学习计划设计

> **v6 新增**：首页改版为「左功能入口栏 + 右 60 天学习计划」。纯客户端，零 API 调用。

## 一、功能概述

打开应用第一眼看到的从「模式选择」变成「今天该干嘛」：

- **左侧入口栏**：写作 / 口语 / 听力 / 背单词四个入口 + 学习身份切换。点击进入各自的全屏工作区（布局完全不变），顶栏「← 返回首页」回到计划页并定位到当前天。
- **右侧 60 天计划**：60 天总览网格 ⇄ 单日详情两层。每天可手填任意条任务，每条含内容、时长、完成勾选；每天可单独设置目标时长（默认 6 小时）。

**非目标（本轮明确不做）**：不绑日历日期（只按 Day 1–60 计数）、不做 AI 分析。

### 为什么不做 AI

用户希望「AI 阶段复盘」在外部（后台）定期处理后把结果展示到界面上。但本项目是纯静态 GitHub Pages，**没有后端**——页面无法自行运行定时任务，外部程序也无法把结果自动写进页面的 localStorage。展示区的输入输出形态（手动粘贴导入？还是别的）尚未确定，故本轮只把位置留出来：

- 数据模型已带 `v: 1` 版本字段，将来加 `reviews` 字段可按版本迁移
- 计划页 `#planOverviewWrap` 与 `#planDetailWrap` 之上可直接插入一个「📊 AI 阶段分析」面板，读同一份 `study_plan_progress` 即可

## 二、数据结构

**主键 `study_plan_progress`** — 单键按身份分区（与 `vocab_progress` 同构）：

```jsonc
{
  "sophia": {
    "v": 3,              // schema 版本，将来迁移靠它分支（v3 起带 phases + tag）
    "manualDay": 12,     // null = 自动推进；1..60 = 用户手动钉住的当前天
    "seeded": "sophia@3",// 已铺过哪份预设（见「预设计划」一节）
    "phases": [          // 总览分块：可选；为空则退化成单个隐式阶段
      { "title": "单项击破与底盘重构", "from": 1, "to": 20 },
      { "title": "题型合流与节奏提速", "from": 21, "to": 45 },
      { "title": "全真对齐与状态封顶", "from": 46, "to": 60 }
    ],
    "days": {            // 稀疏 map，key 是字符串 "1".."60"，没安排的天不写进来
      "1": {
        "target": 300,   // 当天目标时长，单位【分钟】（默认 360 = 6h）
        "tag": "听力 + 写作",   // 当天练哪两科，总览横条上显示；可为 ''
        "tasks": [
          { "id": "t_m1k2x9_0", "text": "主攻 · 听力：…", "min": 120, "done": true },
          { "id": "t_m1k2x9_1", "text": "辅助 · 写作：…", "min": 90, "done": false }
        ]
      }
    }
  }
}
```

`phases` 和 `tag` 都是**显式写进 `spNormalizePlan()` 白名单**的字段 —— 该函数只放行列出的字段，没带过的字段读写一轮就丢。`phases` 校验：`title` 非空字符串、`from`/`to` 是 1..60 整数且 `from <= to`、各阶段互不重叠，坏项丢弃、结果按 `from` 升序。`tag` 非空字符串才保留，否则 `''`。

身份**不持久化**，只存在内存变量 `planIdentity` 里 —— 每次打开自动落到 `PLAN_IDENTITIES` 第一个身份（当前只有 Sophia）。所以没有 `study_plan_identity` 这个键。

### 任务用稳定 id，不用数组下标

数组下标**只表示显示顺序**，`id` 才是身份。这是本功能最关键的正确性决策：如果按下标寻址，用户删掉第 1 行后，正在输入的 `oninput` 仍绑着旧下标，会静默把字写到隔壁任务上；重排后触发的防抖保存同理。有了稳定 id，所有操作都是「按 id 找到 → 改 → 存」，重排只是数组 `splice`，删除不可能误伤幸存行。

id 形如 `t_<base36 时间戳>_<序号>`，单次会话内单调递增，不重复。

### 时长单位

存储一律用**整数分钟**，渲染时拆成「时 / 分」两个输入框。单一权威单位，避免 h/m 进位 bug。新任务默认 0 分钟——时和分是两个独立字段，给个非零默认值会让「在小时框里输 2」变成「2 小时 30 分」，反而费解。

### 读写与脏数据兜底

照抄 Simon 进度（`simonGetProg` / `simonSaveProg`）的「形状校验 + try/catch」范式：

- **读**：`JSON.parse` 失败 → 返回全空；逐身份过 `spNormalizePlan()`，**只替换坏掉的那一侧，另一侧保留**
- **`spNormalizePlan()` 兜底规则**：
  | 脏数据 | 处理 |
  |---|---|
  | 整份不是对象 / 是数组 | 该身份清空 |
  | `manualDay` 不是 1..60 的整数 | 置 `null`（回落自动推进） |
  | `days` 不是对象 | `{}` |
  | day key 越界（如 `"77"`） | 丢弃该天 |
  | `target` 缺失 / NaN / ≤ 0 | 回默认 360 |
  | 任务缺 `id` | 补 `t_legacy_<day>_<index>`（不丢数据） |
  | 任务 `min` 非法 | 回 0 |
  | 任务 `done` 非 `true` | 回 `false` |
- **写**：`try { setItem } catch(e) {}`（QuotaExceeded 静默）
- 容量：60 天 × 8 任务 ≈ 58 KB，远低于配额

## 三、交互流程

```
首页（#homePage）
├─ 左：.home-rail      四个功能入口 + 身份标识（由 PLAN_IDENTITIES 决定，当前只有 Sophia，显示静态标识）
└─ 右：.home-plan
   ├─ #planOverviewWrap   总览：按 phases 分三块可折叠（1–20 / 21–45 / 46–60），每块一列横条
   │                      每条 = Day N + tag + 进度条 + 已完成 a/b；默认只展开当前天所在阶段
   └─ #planDetailWrap     详情：← 返回总览 + Day N + 目标时长 + 任务清单
```

- **总览 → 详情**：点横条 → 详情，并 `scrollTo(0,0)`
- **详情 → 总览**：`← 返回总览`
- **阶段折叠**：点阶段头 `spTogglePhase(i)`，只翻转那一个 section 的 `.open`（不整块重渲染）。展开集合存在内存 `planOpenPhases`（`null` = 默认只开当前天所在阶段），不落盘
- 单日详情里可以「设为当前天」（当前天不显示该按钮）

> **约束**：横条的 id 必须保持 `planCell<d>`（1..60）。`spSyncCells()` 靠这个 id 做「改完任务回总览」的局部刷新，还靠 `#planCell1` 存在与否判断总览是否在屏上。改总览结构时这个 id 约定不能动。

### 重渲染不丢光标（最容易写坏的地方）

`oninput` → 改数据 → `innerHTML` 重建，会把输入框整个换掉，光标丢失，**根本没法打字**。按处理器分三级：

| 级别 | 触发 | 做法 |
|---|---|---|
| 一级 | 改任务文本、改时/分、改当天目标 | **不重建 DOM**。只改内存模型 + 防抖保存，然后用 `textContent`/`innerHTML` 更新纯汇总节点（`#spDaySummary`、总览格子、当前天徽标）。`<input>` 元素本身永不替换 |
| 二级 | 增 / 删 / 上下移任务 | 重建详情，但重建前抓 `document.activeElement` 的 `id` 与 `selectionStart/End`，重建后 `getElementById(keepId).focus()` + `setSelectionRange()`。任务输入框 id 是 `spText_<taskId>`，跨重建存活；新增行显式聚焦新行；上下移时焦点停在被按的按钮上 |
| 三级 | 勾选完成 | **完全不重建**。行 `classList.toggle('done')` + `checkbox.checked` + 更新汇总与总览格子 |

### 属性转义

`escHtml()` 走 `textContent → innerHTML`，**不转义 `"` 和 `'`**，不能用于 `value="..."`——任务文案里一个 `"` 就会撑破标签。所以属性插值一律用专门的 `spEscAttr()`（转义 `& < > " '`），文本节点内容才用 `escHtml`。

### 预设计划：首次进入自动铺好

60 天从零手填门槛太高，所以 `study-plan-preset.js` 提供一份预设计划底稿（`STUDY_PLAN_PRESETS`，按身份提供）：

| 身份 | 方向 | 内容 | 规模 |
|---|---|---|---|
| `sophia` | A类（学术类）· 四科双轨轮换 | 四科齐全，Day A（听力+写作）/ Day B（阅读+口语） | 60 天 × 3–4 条 = 232 条 · 每天 5 小时 |
| ~~`eric`~~ | ~~G类（培训类）· 目标 6.5~~ | **已收起**（2026-09-30）：按钮不再出现，已存的 eric 计划每次启动被清空 | 420 条，底稿存档在不加载的 `study-plan-preset-eric.js` |

### 身份开关：`PLAN_IDENTITIES`

计划页开放哪些身份由 `index.html` 里的一个数组说了算：

```js
const PLAN_IDENTITIES = ['sophia'];
```

它同时驱动三处，改一处就全改：

- `renderHomeRailIdentity()` 据此渲染入口栏的身份按钮（收起的身份没有按钮）
- `spSelectIdentity()` 对不在名单里的 id 直接 `return`，防止手改 HTML 调进来
- `spPresetKey()` 对不在名单里的 id 返回 `null` —— 没有预设可铺

**收起的身份，已存计划会被清掉。** `initStudyPlan()` 读完存储后跑一次 `spPurgeRetiredIdentities()`：凡是不在 `PLAN_IDENTITIES` 里的身份，只要有 days / manualDay 就重置成空计划并写回。**每次启动都清是刻意的** —— 就算它被别处写回来、或有人手改 localStorage，也不会重新冒出来。

恢复 Eric 是两步：把 `'eric'` 加回 `PLAN_IDENTITIES`，再把 `study-plan-preset-eric.js` 里的 plan 贴回 `study-plan-preset.js` 的 `STUDY_PLAN_PRESETS.eric`。

**注意身份是两个模块共用的**：背单词模块有自己的 `vocabIdentity` 和身份选择页，`PLAN_IDENTITIES` 只管计划页。收起 Eric 不会动背单词里的 Eric 进度。

**没有按钮、没有确认框、没有导入流程** —— 第一次进入某个身份时自动铺好，打开就能看到内容，之后完全可改。

唯一的触发点是 `spSelectIdentity()`（切身份时）。`initStudyPlan()` **不触发** —— 身份不持久化，打开应用时 `planIdentity` 还是 `null`，没有任何身份可铺。判定规则：

```
该身份没有预设（key 为 null）  → 什么都不写，直接返回
plan.seeded === 当前预设 key   → 不动（这份已经铺过）
plan.days 非空                 → 只补上 key 标记，绝不覆盖用户已有内容
否则                           → 铺预设
```

**`seeded` 存的是「已经铺过哪一份预设」，形如 `'sophia@1'`，不是 boolean。**

一开始它是 boolean，结果踩了个真实的坑：Sophia 的预设是**后补的** —— 用户在她还没有预设的时候进过一次计划页，代码照样把 `seeded: true` 写进了 localStorage 却什么都没铺；等预设补上，`if (plan.seeded) return false` 第一个分支就返回了，**预设永远铺不进去**，计划页一直是空的。改成存 key 之后，"没预设"这个状态不再留下任何标记，预设一出现就会自动补铺。

存 key 还顺带解决两件事：

- **预设改版可以推送**：把 `plan.v` 提一版（现在两个身份都是 `@1`），改过 key 就和老标记不匹配，老用户下次切身份时自动换成新底稿
- **兼容旧数据**：`spNormalizePlan()` 把旧的 boolean `true` 原样保留（不转成 `null`），这样它既不会被当成"已铺过当前 key"，也不会被当成"全新用户"—— 而是走"`days` 非空就只补标记 / `days` 为空就补铺"的正常分支，当年没铺上的用户就这么被自动补救回来

其余保证不变：

- `spNormalizePlan()` 必须把 `seeded` 带过（漏了就等于每次读取都当成"没铺过"）
- 用户已有的计划永不被覆盖：只在 `days` 为空时才铺
- 逐条删任务不会触发重铺：删空一天只是 `tasks` 变空数组，天的键还在，`days` 非空；就算把 60 天全删光，`seeded` 仍是 `'sophia@1'`，同样不会长回来

**没有清空按钮。** 曾经有过「清空本身份 / 清空全部」，但实测下来日常用不上，而两个不可恢复的破坏性操作摆在计划页右上角风险大于收益，已移除。真要重置，清掉 `study_plan_progress` 再刷新即可 —— 预设会重新铺一份（这正是"清 localStorage"应有的语义）。

**数据校验**：预设数据先深拷贝再走一遍 `spNormalizePlan()`，不直接进内存 —— 预设文件写错了也不会把脏数据带进 localStorage。

**可选依赖**：`spPresetFor()` 对 `STUDY_PLAN_PRESETS` 未定义、或该身份没有预设的情况都返回 `null`。删掉 `study-plan-preset.js` 不会报错，只是没有预设可用（计划为空，用户自己填）。

这份预设是**按 G类常见提分瓶颈排的一家之言**，不是查证过的教学法：写作几乎每天一篇（6.5 分最常卡在写作），听力固定 80 分钟，每周第 7 天降为复盘日（300 分钟）。实际用起来哪项偏重要自己调。

### Sophia 预设：A类四科双轨轮换

来源是一份外部的《60 天备战雅思 A类》规划方案（v2，取代了早先只有听力的 v1）。核心是**双轨轮换**：每天四个板块、四科从不断档。

| 轨道 | 出现的日子 | 晨间微习惯 45′ | 主攻模块 120′ | 辅助模块 90′ | 晚间微习惯 30′ |
|---|---|---|---|---|---|
| **Day A** | 奇数日 | 听力：Part 4 学术词听写 30 词 | **听力**专项 | **写作**核心推导 | 口语：Part 1 跟读 |
| **Day B** | 偶数日 | 阅读：长难句 2 句 + 同义替换卡 | **阅读**慢练 | **口语**母题串联 | 写作：好词好句复盘 |

三阶段：

| 阶段 | 天数 | 听力（Day A） | 阅读（Day B） | 写作（Day A 辅助） | 口语（Day B 辅助） |
|---|---|---|---|---|---|
| P1 单项击破 | 1–20 | 地图题（1–10）→ Part 1 稳分（11–20） | Passage 1/2 慢练 22–25′，题型优先 | 旧文切片诊断（1–5）→ 逻辑链攻坚四步推导 | 5 大母题每场一个，只记 6 个关键词 |
| P2 题型合流 | 21–45 | Part 1+2 组合拳 + Part 4 结构预判 | P1+P2 双篇连做限时 40′ | 大作文限时 / 小作文图表 **交替** | 当季话题卡串母题 + Part 3 四步论证 |
| P3 全真对齐 | 46–60 | 模考日 7 次（偶数日）· 复盘日 7 次（奇数日）· Day 60 封卷 | | | |

落地时的判断：

1. **双轨的「日」＝ 本功能的 Day 序号，不是星期。** 本功能明确不绑日历日期（见「一、功能概述」的非目标），所以 Day A/B 直接落在奇偶日：Day 1 是 Day A，Day 2 是 Day B，以此类推。原方案里的「第 1–10 天 / 第 11–20 天」在双轨下意味着**听力只有 5 场**（奇数日），所以任务文案写的是「精做 2 篇」而不是「每天精做 2 篇」。
2. **P3 的模考日落在偶数日，Day 60 是例外。** Phase 3 从 Day 46 起算，46 是偶数 —— 所以模考日 = 46/48/…/58（正好 7 次，对上原方案的「共 7 次全真模拟」），复盘日 = 47/49/…/59。**Day 60 单独作为封卷日**，不按奇偶走。原方案同时写了「共 7 次模考」和「考前 3 天封卷」，两者在 15 天里塞不下（7 次模考本身就要占 14 天）——这里选了保住「7 次」这个明确的数量，封卷压到 Day 60 一天。**改这一段时要盯住 Day 46 落在哪一侧。**
3. **写作辅助在两个题型间交替**（Phase 2 的 13 个 Day A ＝ 7 次大作文 + 6 次小作文，小作文内部再分动态图 / 静态图），对上原方案的「每周各 2 篇」。
4. **每日目标时长设 300 分钟（5 小时），任务明细合计 285 分钟（4h45m）。** 原方案三处数字对不上：标题写「5.25 小时/天」、括号里写「两个微习惯各 45 分钟」（合 5 小时）、明细里晚间微习惯写 30 分钟（合 4h45m）。这里取明细的 45/120/90/30 铺任务，目标时长按「每天投入 5–5.5 小时」取下限 300。所以正常日会显示「已排 4h45m / 目标 5h」，差的那 15 分钟是机动。**Phase 3 的模考日只排 175′、复盘日 150′、封卷日 135′**，与 300 的目标差得更远 —— 原方案对这三类日只给了内容没给时长，复盘日尤其简略（只写了「错题溯源」），这是照搬原文的结果。
5. **v2 会替换掉 v1 吗？不会。** `plan.v` 提到了 2，预设 key 变成 `sophia@2`；但铺预设的规则里「用户已有内容绝不覆盖」优先 —— 已经铺过 v1 听力专案的设备，切身份时只会把标记升级成 `sophia@2`，旧内容原样留着。要换成 v2 得先清掉那份计划（清 `study_plan_progress`，或开无痕窗口）。


## 四、当前天与自动推进

```js
spAutoDay(plan):
  扫 1..60，跳过没有任务的天
  命中第一个"有任务且存在未勾选"的天 → 返回它
  否则：没有任何安排 → Day 1
        已安排的都做完了 → min(最后有内容的天 + 1, 60)

spCurrentDay(plan):
  manualDay 是 1..60 的整数 → 用它（手动优先）
  否则 → spAutoDay(plan)
```

语义说明：

- **顺序使用下"全勾完自动跳到下一天"自然成立**——第 N 天勾完，第一个未完成天就是 N+1
- **已安排的都做完了会跳到下一天（而不是停在做完的那天）**，即使下一天还没安排内容。这样「一天一天往后排计划」的用法里，做完当天就会被指到下一天去安排，而不是对着一个已完成的天发呆
- 第 60 天做完 → `min(61, 60)` = 60，不越界；总览出现「🎉 60 天计划全部完成」横幅
- **手动指定持久生效**（这正是「可手动改」的意义），只有点「↺ 定位当前天」才清除它。不在完成时静默清除，否则被钉住的天会莫名跳走
- 跳过前面的天直接做完第 40 天时，指针会回落到第 1 天（"你还欠第 1 天"）
- 空天不算「未完成」，会被跳过——用户还没安排的天不该被判成欠债

## 五、身份隔离

沿用背单词模块那套身份名（Eric / Sophia），各有一份独立的 60 天计划。**计划页当前只开放 Sophia**，见上一节的 `PLAN_IDENTITIES`。

- **不持久化身份**：`planIdentity` 只是内存变量，`initStudyPlan()` 刻意**不读**任何存储。每次打开应用都从「选身份」开始，选完才渲染计划
- **不复用 `vocabIdentity`**：那是背单词模块自己的变量，两个模块各管各的。进背单词不会被计划的身份影响，反之亦然
- **入口栏可随时切换**：计划页左栏的身份分段切换，点了立即换到另一个身份的计划（数据互相独立）。当前名单里只有 Sophia，所以看不到切换
- **数据仍然按身份持久化**：身份不记，但 `study_plan_progress` 里两个身份的数据都在。重选同一个身份，内容原样回来

### 为什么不做密码

曾经实现过「计划页身份密码」（每身份一个、存 `study_plan_pw`、解锁态仅内存）。后来去掉了，原因：

1. **纯前端没有真安全**。数据和密码都在 `localStorage` 里，`F12` 就能读计划内容，也能删掉密码项直接进来。既然挡不住懂行的人，它提供的价值就只有「防随手翻」
2. **为了这点价值承担的复杂度不成比例**：多一个存储键、三个状态机（`unset`/`locked`/`off`）、一套设置/解锁/忘记密码界面，还有一个真实的锁死风险 —— 实测中确实出过一次「设完密码进不去」，根因是加锁分支里误清了父容器 `#planOverviewWrap` 的 innerHTML，把总览网格容器永久删掉了
3. **「每次进去选一下身份」已经够用**：共用设备时，身份选择本身就把两人的计划分开了

真要做访问控制，得走后端验证，这个纯静态项目做不到。

## 六、响应式

| 断点 | 行为 |
|---|---|
| > 768px | 首页两栏 `260px 1fr`；总览三个阶段卡片纵向堆叠，阶段内每天一行横条：`Day N` → tag → 进度条（弹性占满中间）→ 完成度文字（靠右） |
| ≤ 768px | 首页单栏；入口栏改**网格**（`repeat(auto-fit,minmax(140px,1fr))`），四个功能 2×2 一屏全见；阶段头允许折行（标题独占一行），横条收窄间距、tag 变小；任务行折行（勾选 + 文本一行，时长 + 操作一行） |

> ⚠️ **CSS 顺序陷阱**：本项目踩过「基础规则写在 `@media` 之后被覆盖」的坑（见 CLAUDE.md）。总览的横条/阶段基础规则统一放在 `<style>` 里 675-702 这段（在媒体查询之前），窄屏覆盖只写在 `@media(max-width:768px)` 里。

### 总览横条的三态配色

| 状态 | 横条 | 进度条 | 文案 |
|---|---|---|---|
| 未安排（0 个任务） | 灰底 | 空轨道 | `未安排` |
| 进行中 | 常态 | **蓝** `--suggest` | `已完成 3 / 4` |
| 全部完成 | 浅绿底 | **青绿** `--correct` | `✓ 全部完成 · 4h45m`（文字转绿加粗） |

进行中用蓝而不是绿，是为了和「已完成」的青绿拉开色相 —— 两者都用绿系时在进度条上几乎分不出来。当前天是横条整条 `--accent-soft` 浅绿底 + Day 号转 accent 色，属于独立的"你在哪"通道，不和进度颜色打架。

入口栏**故意不走 `.sidebar` 的抽屉模式**：横向条不需要切换按钮、遮罩和新的顶栏接线，而且四个入口始终可见，比藏在 ☰ 后面更符合"整合到入口处"的诉求。

## 七、边界情况

| 情况 | 处理 |
|---|---|
| 删除中间的任务 | 有内容时 `confirm()` → 按 id `splice` → 立即存 → 恢复焦点 |
| 重排 | ↑/↓ 按钮（无拖拽库，无构建步骤，上下移 10 行且键盘可达）；首个 ↑ 禁用、末个 ↓ 禁用 |
| 空的一天 | 详情显示空态 + `＋ 添加任务`；总览横条灰底虚化；`spAutoDay` 跳过 |
| 空计划（60 天全空） | 60 条虚化横条；当前天 = 1；无报错、无 NaN |
| 某天任务被全删 | 该天变空 → 自动推进跳过；若它原是当前天，重算出下一个未完成天 |
| 第 60 天做完 | 不越界；总览出现完成横幅 |
| 想彻底重置 | 无 UI 入口（清空按钮已移除）。清掉 `study_plan_progress` 再刷新，预设会重新铺一份 |
| 关页面时还有防抖未落盘 | `beforeunload` 里 `spSaveNow()` 兜底；结构性改动立即存，不走防抖 |
| 存储脏数据 | 读时归一化，任何情况都不抛异常 |

## 八、已知风险

1. **打字时光标被重渲染打断** —— 概率最高。靠上面的一/二/三级规则规避；回归时优先测「输一段长文本，光标不跳」。
2. **`escHtml` 不转义引号** —— 属性插值一律走 `spEscAttr`，别混用。
3. **不受限的 `switchTab`（写作模块）** —— 它 document 级清 `.tab`/`.tab-content`。计划**完全不用** `.tab`/`.tabs` 类，全部走 `.plan-*`/`.home-*`；不要在单日详情里加 Tab。
4. **硬编码 `57px`（顶栏高度）** —— 新的 sticky 入口栏和 `min-height` 原样复用 `calc(100vh - 57px)`；不要往顶栏上方再插行，否则常量漂移。
5. **vocab 与 plan 身份不一致** —— 靠 `selectVocabIdentity` 里的镜像行维持；该行若被删，计划侧会退回上次显式选择的身份（不会崩，只是不再自动跟随）。
6. **DOM id 撞车** —— 计划所有 id 带 `plan`/`sp` 前缀（`planCell12`、`spText_<taskId>`、`spDayTotal`），避免与写作的 `taskCard{i}`/`taskAnswer{i}`/`taskList` 冲突。
7. **既有三套 stat 三元组重复** —— `.speaking-stat-*` / `.listening-stat-*` / `.vocab-stat-*` 是三份重复。计划模块**没有再添第四份**：单日详情的信息由一行 `#spDaySummary`（已排 / 目标 / 任务完成数）表达即可，再摆一个 stat 网格只是重复。将来若要统一这三套，可一次性处理。
